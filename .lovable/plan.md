# Демо-контент: фото по возрасту, город, автообновление + AI-подсказки ответов

Работа делится на два отдельных этапа, как вы и просили: сначала пункты 1–3 (демо-контент), потом отдельно пункт 4 (AI-ассистент). Ниже — план обоих, но в код они пойдут разными шагами.

## Что подтвердилось при проверке

- Подбор «на день» вообще не фильтрует по городу: в запросе есть возраст, видимость, блокировки, вытеснение демо — но условия по городу нет. Поэтому Никита из Екатеринбурга попадает пользователю из Новосибирска. Объявления «Рядом», наоборот, город учитывают одинаково для реальных и демо-записей.
- В демо-скрипте город выбирается по номеру анкеты, а фото — из общего списка восьми снимков, без связи с возрастом и полом. Отсюда «Светлана, 32» с фото женщины 60+.
- Никакого автообновления демо-контента нет: только запуск скрипта вручную.
- Подсказки в чате сейчас не от AI: это шаблонная фраза по общему интересу.

## Этап 1 — демо-контент (пункты 1–3)

### Возраст, пол и фото
- Дополнить набор снимков людей так, чтобы на каждый диапазон (18–25, 26–35, 36–50, 50+) было минимум 2 фото на каждый пол — 16 снимков. Существующие 8 распределяются по диапазонам, недостающие генерируются.
- В демо-скрипте у каждой анкеты явно указываются пол и возраст; фото подбирается строго из ячейки «пол + возрастной диапазон», по кругу внутри ячейки, чтобы не повторялось одно и то же лицо.
- Самопроверка в скрипте: если для анкеты не нашлось фото своей ячейки или диапазон не совпал, скрипт печатает предупреждение с именем и возрастом и не подставляет чужое фото.

### Город
- В подбор «на день» добавляется фильтр по городу пользователя: одинаково для демо и реальных анкет. Если город в профиле не заполнен, подбор работает как сейчас (без гео-сужения), чтобы новые пользователи не видели пустой экран.
- Мультигеография — только по явному параметру запроса, а не как побочный эффект.
- «Рядом» остаётся как есть (фильтр уже корректный), добавляется проверка на реальных данных.
- После правок демо-данные пересеваются и проверяется: с фильтром «Новосибирск» ни в лентах, ни в объявлениях нет записей других городов.

### Ежесуточное обновление
- Новый облегчённый скрипт обновления: сдвигает даты демо-объявлений и демо-встреч на «сегодня / ближайшие дни» и с вероятностью ~10–15% заменяет часть демо-анкет и демо-объявлений новыми вариациями того же типа и города, сохраняя примерно постоянный объём по городу и категории.
- Все запросы жёстко ограничены отметкой «демо»: записи реальных пользователей не читаются на запись ни при каких условиях.
- Запуск — расписанием внутри самого серверного процесса (`node-cron`, 04:00 по времени сервера), чтобы логика жила в репозитории и деплоилась вместе с кодом.
- Каждый запуск пишет в лог сервера сводку: сколько записей обновлено и сколько заменено (видно в `pm2 logs`).
- Приоритет реальных данных и автоскрытие демо при достаточном числе реальных записей не меняются; проверяется, что обновление их не ломает.

## Этап 2 — AI-ассистент (пункт 4)

### Подсказки ответа в чате
- Рядом с полем ввода появляется кнопка «Предложить ответ». По нажатию сервер берёт последние 5–10 сообщений и через LLM (совместимый с OpenAI endpoint, ключ из окружения — в проекте уже есть переменная для AI-функций верификации) возвращает 2–3 короткие реплики на русском.
- Варианты показываются чипами над полем ввода, тап подставляет текст в поле; отправка — только вручную самим пользователем. Автоотправки нет.
- Ограничение: не чаще одного вызова в 10 секунд на диалог, через уже используемый механизм лимитов; при превышении — понятное сообщение.
- Если ключ LLM не задан, кнопка не показывается, экран работает как раньше.

### Автоответ в объявлениях
- У автора объявления — переключатель «Автоответ на вопросы». При включении на новый вопрос генерируется черновик по тексту объявления и вопросу и показывается автору с пометкой «Черновик от AI — проверьте перед отправкой» и кнопкой «Отправить».
- Отдельная явная галочка «Разрешить автоответ без подтверждения» при создании объявления: только тогда через 2 часа без ручного ответа черновик уходит сам и в сообщении видна пометка «(автоответ)».

### Границы
- Реальный человек никогда не переписывается с демо-анкетой под видом живого: демо-профиль открывается только для просмотра, при попытке написать — сообщение «Это демо-профиль для примера, реальные пользователи скоро появятся».
- Никаких фоновых обращений к LLM без действия человека, кроме опционального автоответа, разрешённого автором.
- Новые точки API и настройки автоответа описываются в документации API.
