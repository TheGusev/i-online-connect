# Приведение приложения к «боевому» состоянию: ввод, сессия, опросник, реальные данные

## Что подтверждено проверкой кода

- `src/routes/__root.tsx` (строка 82): viewport без `interactive-widget`, экраны на `min-h-screen`; в `src/routes/onboarding.tsx` на каждый шаг и на каждое «печатает…» вызывается `scrollIntoView({ behavior: "smooth" })` — при открытии клавиатуры это и даёт «уезжающий» экран.
- Сессия нигде не восстанавливается: `useSessionStore` живёт только в памяти, токен лежит в localStorage, у `/` нет проверки авторизации — поэтому после регистрации снова видно приветственный экран.
- Шаг «ценности» (`values`) — три свободных `TextArea`, выбора из списка нет.
- Мок-данные включаются флагом `VITE_USE_MOCKS` и используются во всех эндпоинтах `src/api/endpoints/*`. Скриншоты с `maksim@yaonline.app` и «Максим, 29 лет» — это моки (`src/api/mocks/*`).
- **Главная проблема данных**: на backend вообще нет ни одного маршрута с параметром. Есть только `/auth/*`, `/onboarding`, `/profiles/me`, `/matching/daily`, `/matching/candidates`, `/chat/conversations`, `/spaces`, `/settings`, `/settings/account`, `/settings/notifications`, `/trust/summary`, `/trust/reports`. Фронтенд же зовёт ещё 13 адресов, которых нет: `/profiles/:id`, `/profiles/:id/detail`, `/chat/conversations/:id`, `/chat/conversations/:id/messages`, `/read`, `/starters`, `/meetings`, `/spaces/:id`, `/join`, `/leave`, `/spaces/:id/events/:eventId/rsvp`, `/spaces/:id/messages`, `/matching/candidates/:id/reaction`, `/settings/password`, `/trust/verification`.
- В `server/migrations/001_init.sql` нет ни одного `INSERT` — справочник интересов пуст.

## Что делаем

### 1. Ввод не «уезжает» (мобильная клавиатура)
- В `__root.tsx` viewport: `width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content`.
- Заменить `min-h-screen` на `min-h-dvh` в онбординге и `AppShell`.
- В онбординге: автоскролл только при смене шага (не при `typing`/`submitState`), `block: "nearest"`, без `smooth`; поле ввода не перекрывается — нижний отступ с `env(safe-area-inset-bottom)`.

### 2. После регистрации приветственного экрана больше нет
- Токен сохраняется (как сейчас), плюс восстановление сессии при старте: `authApi.getCurrentUser()` при наличии токена, результат в `useSessionStore`.
- `/` — при активной сессии сразу редирект на `/feed`; приветственный экран только для гостей.
- Защита приватных маршрутов (`/feed`, `/chat`, `/spaces`, `/profile/*`, `/settings`): без сессии — редирект на новый экран входа `/auth` (email + пароль, ссылка «пройти онбординг»).
- Выход из аккаунта чистит токен, стор и уводит на `/`.

### 3. Опросник: выбор вместо свободного текста
- Шаг «ценности» переводим на чипы с мультивыбором по трём вопросам:
  - Ценности: Честность · Забота · Свобода · Надёжность · Юмор · Развитие · Семья · Уважение границ · Любознательность · Спокойствие
  - Радует в общении: Искренность · Глубокие разговоры · Легкий юмор · Общие планы · Внимание к деталям · Тишина вдвоём · Совместные дела
  - Недопустимо: Ложь · Грубость · Ревность · Игры в молчание · Неуважение · Исчезновения без слов
- Можно добавить свой вариант (как в шаге интересов), 1–3 выбора на вопрос. Ответ в чате — списком через `·`.

### 4. Чистка моков и реальные данные
- Полностью удаляем `src/api/mocks/*`, флаг `VITE_USE_MOCKS` и все ветки `USE_MOCKS` в `src/api/endpoints/*`, `src/api/client.ts`, `.env`, `.env.example`, документации. Остаётся один путь: реальный API.
- Дописываем на backend все 15 отсутствующих маршрутов (профиль другого пользователя и его detail, чат: диалог/сообщения/прочитано/подсказки/встречи, пространства: карточка/вступить/выйти/RSVP/сообщения, реакция на кандидата, смена пароля, заявка на верификацию) строго на существующих таблицах из `001_init.sql`, с `requireAuth` и Zod-валидацией.
- Миграция `002_seed_interests.sql`: только справочник интересов (реальные метки), никаких фиктивных пользователей.
- Пустые состояния везде честные: нет данных — показываем «пока никого/пусто», а не демо-карточки.

## Технические детали

- Новые файлы: `src/routes/auth.tsx` (вход), `src/features/onboarding/ValuesPicker.tsx`, `server/migrations/002_seed_interests.sql`, новые обработчики в `server/src/routes/{profile,chat,spaces,matching,settings,trust}.ts`.
- Восстановление сессии — в `__root.tsx` через `useQuery` + `authApi.getCurrentUser` (без loader'ов, чтобы не ломать prerender статической сборки).
- Черновик онбординга: `values` остаётся объектом `{ values, joy, dealbreakers }`, но строки собираются из выбранных чипов — контракт `POST /api/onboarding` не меняется.
- Локализация: новые ключи для шага ценностей и экрана входа в `ru.json` и `en.json`.
- Проверка: `npm run build:static` без ошибок, прогон онбординга в браузере (регистрация → профиль → редирект на `/feed`, повторный вход не показывает лендинг), проверка отсутствия строки `USE_MOCKS` в бандле.
