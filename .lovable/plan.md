# Чат без дублей, компактный ввод и голосовые сообщения

## Результат
Личный чат станет устойчивым к повторным сообщениям, поле ввода будет расти вместе с текстом, экран перестанет сдвигаться при мобильной клавиатуре, а рядом с вводом появится компактная запись голосовых сообщений. Изменения будут разделены по этапам, чтобы каждый блок можно было отдельно проверить и выпустить.

## 1. Устранить дублирование сообщений

- Добавить каждому исходящему сообщению клиентский UUID `tempId` до первого запроса.
- Сразу показывать один локальный пузырь со статусом отправки; HTTP-ответ и WebSocket-эхо будут заменять его по `tempId`, а не добавлять второй.
- На сервере принимать и возвращать `tempId`, хранить его как идентификатор идемпотентности и защищать уникальным индексом в рамках автора/диалога. Повторный запрос после обрыва связи вернёт уже созданное сообщение.
- Оставить единственную отправку через `onSubmit`; Enter вызывает отправку формы, кнопка остаётся `type="submit"` без отдельного запроса.
- На клиенте дополнительно дедуплицировать историю по реальному `id`, включая гонку «сначала WebSocket, затем HTTP» и повторное подключение.
- Заблокировать повторное нажатие, пока текущая отправка не завершилась; для неудачного сообщения сохранить безопасное повторение с тем же `tempId`.
- Сохранить существующую корректную очистку WebSocket и добавить проверки, что повторный монтаж не создаёт вторую подписку.

## 2. Компактное растущее поле ввода

- Вынести общий компактный `ChatComposer`, чтобы личный и групповой чат одинаково работали на телефоне.
- Использовать `textarea` высотой от одной строки до 5–6 строк; пересчитывать `scrollHeight` при вводе, очистке, вставке текста и выборе подсказки.
- После достижения максимальной высоты включать прокрутку только внутри поля, без обрезания текста.
- При росте поля уменьшать доступную область истории; шапка и панель ввода не перекрывают сообщения.
- Сохранить привычное поведение: Enter отправляет, Shift+Enter добавляет перенос; во время отправки повторное действие недоступно.
- Сделать мобильную панель плотной: стабильные кнопки не меньше удобной зоны касания, `min-w-0` для текста, без переноса и наложений на ширине 393 px.

## 3. Закрепить исправление мобильной клавиатуры

- Оставить `visualViewport` единым источником видимой высоты и учитывать одновременно `height` и `offsetTop`.
- Слушать оба события `resize` и `scroll`, корректно снимать обработчики и не создавать несколько подписчиков на одном экране.
- Зафиксировать весь чат по координатам видимой области; отдельно прокручивается только история сообщений.
- Панель ввода размещать у нижней границы `visualViewport`, без `bottom: 0`, двойного keyboard-inset и лишнего safe-area при открытой клавиатуре.
- Нижнее меню скрывать при вводе; последнее сообщение после открытия, закрытия и изменения высоты клавиатуры остаётся в кадре.
- Тот же принцип применить к общему чату пространства, чтобы регрессия не осталась во втором варианте чата.

## 4. Голосовые сообщения

- Когда текст пуст, показывать микрофон; когда введён текст — кнопку отправки. В неподдерживаемом браузере микрофон скрывать, не затрагивая обычные сообщения.
- Запускать запись удержанием микрофона через pointer events; показывать компактную красную индикацию, таймер и простую пульсацию без тяжёлого пакета.
- Свайп влево отменяет запись, отпускание отправляет, достижение 3 минут автоматически завершает запись. Добавить доступный сценарий управления без жеста.
- Перед записью явно запрашивать микрофон и показывать понятные состояния: доступ запрещён, микрофон занят/не найден, небезопасное соединение, запись не поддерживается.
- Выбирать формат через feature detection: WebM/Opus для Chrome/Android и MP4/AAC для iOS Safari.
- Добавить отдельную загрузку голосового сообщения, привязанную к диалогу: максимум 10 МБ и 180 секунд, проверка контейнера по содержимому, доступ только участникам диалога.
- Расширить сообщение типом `voice` и полями URL, длительности и MIME-типа отдельной миграцией; старые текстовые сообщения останутся совместимыми.
- Хранить аудио отдельно от фото профиля и объявлений, раздавать через существующий защищённый медиапуть.
- Отправлять голосовое через тот же WebSocket, историю, отметки прочтения, уведомления и push; текст уведомления — «Голосовое сообщение».
- В истории показать компактный плеер: play/pause, текущий прогресс, длительность и состояние отправки/ошибки. Использовать нативное аудио и собственные компактные элементы без новой зависимости.

## Технические изменения

- **Фронтенд:** тип `Message`, API чата, optimistic cache, WebSocket reconciliation, общий composer, контроллер записи, голосовой пузырь и мобильная компоновка личного/группового чата.
- **Backend:** идемпотентная отправка текста по `tempId`, multipart-маршрут голосового сообщения, проверка доступа/размера/содержимого, сохранение аудио и единая публикация события.
- **База:** новая миграция после `014` с `client_temp_id`, типом `voice`, аудиополями и уникальным индексом идемпотентности; существующие строки не переписываются.
- **Документация:** обновить API, схему БД, лимиты медиа и порядок применения миграции. Новых переменных окружения не планируется.
- Работу вести четырьмя логически отдельными наборами изменений в порядке из PDF. Git-коммиты из среды не создаются, но итоговый отчёт сохранит такое же разделение для отдельного выпуска.

## Проверка

- Дубли: несколько быстрых отправок, Enter и кнопка, медленный HTTP, WebSocket раньше/позже HTTP, потеря и восстановление сети, повтор неудачного сообщения, повторный монтаж экрана.
- Ввод: одна строка, 6+ строк, вставка длинного текста, переносы, очистка после отправки; история не перекрывается.
- Клавиатура: размеры 393×626 и другие мобильные экраны, открытие/закрытие клавиатуры, iOS-подобный `offsetTop`, личный и общий чат, портретная/альбомная ориентация.
- Голос: разрешение/отказ, отмена свайпом, отпускание и автостоп, WebM и MP4, лимиты 10 МБ/180 секунд, воспроизведение, повтор после ошибки, доставка второму пользователю и push.
- Запустить проверки фронтенда, backend и статической сборки; провести браузерный сценарий с двумя сессиями и искусственно замедленной сетью.
- Реальный iPhone Safari проверить при доступности устройства; если его нет в среде, в отчёте прямо отметить ограничение и не выдавать эмуляцию за физическое тестирование.

## Итоговый отчёт

- По каждому из четырёх пунктов перечислить изменённые и новые файлы.
- Отдельно указать миграцию, пакеты и переменные окружения; если их нет — зафиксировать это явно.
- Дать прямой результат ручной проверки дублей, медленной сети, переподключения, мобильной клавиатуры и голосовой записи.
