# Анти-спам в разделе «Рядом»: что уже есть и что доделать

## Ответ на замечание

Ограничение частоты на создание объявлений **попало в тот же коммит**: `POST /api/listings` уже ограничен 20 запросами в час, плюс есть глобальный лимит 300 запросов в минуту на весь API. Так что «Рядом» не остался без защиты.

Но защита не полная — в текущем виде счётчик считается **по IP-адресу, а не по аккаунту**. Значит один человек может обойти лимит, сменив сеть, а несколько людей из одной сети (офис, мобильный оператор) наоборот мешают друг другу. Плюс не ограничены два соседних действия, через которые тоже можно спамить: отклики на чужие объявления и правка своих.

## Что предлагаю сделать

1. **Считать лимиты по пользователю, а не по IP** — для всех защищённых разделов, включая «Рядом». Для гостевых маршрутов (вход, регистрация) остаётся IP.
2. **Ограничить отклики**: не более 30 откликов в час с аккаунта — сейчас лимита нет, а каждый отклик создаёт диалог и уведомление автору.
3. **Ограничить правки**: не более 60 изменений объявлений в час.
4. **Ограничить общее число активных объявлений** у одного человека (предлагаю 15). Лимит по времени не мешает накопить сотни объявлений за неделю; лимит на количество — мешает.
5. **Понятные сообщения об ошибке** вместо стандартного технического текста: «Слишком много объявлений подряд, попробуйте позже» — на русском, в тоне приложения.
6. **Фронтенд**: показывать это сообщение в форме создания и на кнопке отклика, а не молча гасить действие.

## Технические детали

- `server/src/index.ts`: `keyGenerator` → `userId` из проверенного токена с откатом на `request.ip`; общий `errorResponseBuilder` с русским текстом.
- `server/src/routes/listings.ts`: добавить `config.rateLimit` на `POST /:id/respond` и `PATCH /:id`; в обработчике создания — проверка счётчика активных объявлений автора (`state = 'active' AND expires_at > now()`), при превышении `badRequest` с понятным текстом.
- Миграции не нужны — только проверка запросом.
- Фронтенд: `src/routes/nearby.new.tsx` и `src/routes/nearby.$id.tsx` — вывод текста ошибки из ответа API.
- Проверка: локальный прогон — серия запросов на создание/отклик до срабатывания лимита, затем нормальный сценарий после сброса окна.

## Не входит в этот шаг

Админка, TOTP и скрытый путь — как договаривались, отдельной задачей.
