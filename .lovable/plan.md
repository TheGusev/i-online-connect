# Раздел «Рядом»: фронтенд + сквозная проверка

## Состояние бэкенда (проверено)

- Миграция `server/migrations/005_listings.sql` есть: `listings`, `listing_media`, `listing_responses`, `user_needs`, `notifications`, значение `listing` в `report_source`.
- Эндпоинты есть: `GET/POST /api/listings`, `GET /api/listings/mine`, `GET /api/listings/:id`, `PATCH /api/listings/:id`, `POST /api/listings/:id/close`, `POST /api/listings/:id/respond` (создаёт обычный диалог), `GET/PUT /api/listings/needs`, `GET /api/notifications`, `POST /api/notifications/read`, WS-канал уведомлений.
- Клиенты `src/api/endpoints/listings.ts` и `notifications.ts` уже написаны. Значит фронтенд можно делать сразу.
- Один нюанс: на всю ветку `/api/listings` навешен `requireAuth`, поэтому гость данных из API получить не может (см. решение ниже).

## Что делаем

### 1. Навигация
- В `src/components/layout/nav-items.ts` добавляем пункт «Рядом» (`/nearby`, иконка `MapPin`) — он автоматически появится в `BottomNav` и `SideNav` с тем же активным стилем. Сетка нижней навигации меняется с 4 на 5 колонок.
- В подвал лендинга (`src/routes/index.tsx`) добавляем ссылку «Рядом» рядом с «О проекте / Правила / Поддержка».
- Ключи `nav.nearby` и подписи блока добавляем в `ru.json` и `en.json`.

### 2. `/nearby` — витрина
- Фильтры сверху: город (текстовое поле, по умолчанию город из профиля — он приходит в ответе API полем `city`), категории чипами (Продажа, Услуга, Досуг, Попутчик, Помощь) на `Chip`, поиск по заголовку.
- Карточки на `Card`: фото (если есть), заголовок, категория чипом, цена, город, дата, `TrustBadge` автора; ссылка на `/nearby/$id`.
- Список грузим одним запросом с `limit`, как это сделано в `/feed` и `/spaces` (там нет пагинации), плюс кнопка «Показать ещё», увеличивающая `limit`. Отдельную серверную пагинацию не вводим.
- Пустое состояние: «Пока нет объявлений в вашем городе — станьте первым» + кнопка на `/nearby/new`.
- Гость: страница индексируется (свой `head()` с title/description), но вместо списка показываем заглушку «Войдите, чтобы видеть объявления в вашем городе» с описанием категорий и кнопкой на `/onboarding` — API объявлений требует авторизации, публичную выдачу без бэкенд-правок отдать нельзя.

### 3. `/nearby/new` — создание
- Форма: категория чип-группой, заголовок, описание, цена (поле скрывается для «Досуг» и «Помощь»), фото (загрузка через `mediaApi.uploadMedia`, тот же приём, что в `MediaManager`), срок актуальности 7/14/30 дней.
- Город не спрашиваем — сервер берёт из профиля.
- После публикации — `toast.success` и редирект на `/nearby/$id`.

### 4. `/nearby/$id` — карточка
- Полное описание, галерея фото, автор с `TrustBadge` и ссылкой на профиль.
- «Откликнуться» → `respondToListing` → редирект в `/chat/$id` с полученным `conversationId`.
- «Пожаловаться» → существующий `ReportModal` с источником `listing`.
- Своё объявление: вместо отклика — «Редактировать» (заголовок/описание/цена) и «Закрыть объявление».

### 5. «Мои потребности» в настройках
- Новая секция `NeedsSection` в `/settings` (иконка `Handshake`) с чекбоксами пяти категорий.
- Чтение `getMyNeeds`, сохранение `setMyNeeds` через `useMutation` с инвалидацией ключа — по образцу остальных настроек.

### 6. Уведомления
- Колокольчик в `TopBar` сейчас ведёт в `/settings` и счётчик не подключён. Подключаем `getNotifications` + WS-канал уведомлений: живой счётчик непрочитанных и всплывающий список последних; клик по элементу ведёт на `/nearby/$id` и помечает прочитанным.
- Бэкенд уже создаёт уведомления при публикации (совпадение город + категория из `user_needs`) — правки на сервере не нужны.

### 7. Проверка флоу — честная рамка
В песочнице нет запущенного Node-бэкенда и PostgreSQL (`VITE_API_URL` указывает на `localhost:4000`), поэтому сквозной тест на реальном аккаунте выполняется так:
- поднимаю локально Postgres + `server` (миграции + `npm run dev`), если это удаётся в песочнице, и прохожу все шаги а–е браузером;
- если поднять БД в песочнице не выйдет, честно фиксирую это и прохожу браузером всё, что не требует API (навигация, гостевая витрина, формы, валидация), плюс даю точный чек-лист шагов а–е для запуска на вашем сервере.
В отчёте будет по каждому шагу: что проверено, что сработало, что нет.
