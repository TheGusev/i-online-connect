# Фавиконка, создание пространства и загрузка фото

## 1. Своя фавиконка вместо дефолтной

Сейчас в `public/` лежит только шаблонный `favicon.ico`, и `__root.tsx` ссылается на него — отсюда чужая иконка во вкладке.

- Сгенерировать квадратный знак «Я» в фирменном коралловом (#FF6B5B) на тёплом фоне.
- Положить как `public/favicon.png` (64×64) и подключить в `head().links` корневого маршрута.
- Удалить шаблонный `public/favicon.ico`, чтобы старая иконка больше нигде не отдавалась.

## 2. Кнопка «Создать пространство» неактивна

Форма включает кнопку только когда название ≥ 3 символов И описание ≥ 20 символов, но пользователю об этом нигде не сказано — выглядит как «всё заполнил, а кнопка мёртвая».

- Показывать под полями понятные подсказки-счётчики («ещё N символов описания»).
- Разрешать нажатие всегда: при неполных данных подсвечивать конкретное поле с текстом ошибки вместо блокировки.
- Ошибку с сервера показывать тостом (сейчас 400 уходит в пустоту).

## 3. Обложка пространства: нельзя загрузить своё фото

Две отдельные причины:

- В форме есть только 6 готовых картинок, загрузки файла нет.
- Сервер принимает обложку валидатором «полный URL», поэтому даже путь вида `/media/...` или путь готовой картинки он отвергает — то есть создание с обложкой ломается по 400.

Что делаем:

- Добавить в форму загрузку своего файла с превью (рядом с готовыми обложками) и валидацию типа/размера.
- Добавить серверный приём файла обложки, файл кладётся в общее медиа-хранилище.
- Смягчить проверку обложки на сервере: принимать и относительный путь медиа, и полный URL; посторонние адреса не пропускать.

## 4. Фото профиля не загружается / не видно

Найденная причина: медиа отдаются по относительному префиксу `/media`, который в проде раздаёт Nginx, а сам backend файлы не отдаёт вовсе. В результате картинка запрашивается не с того адреса и не находится — фото «залилось, но не видно».

- Backend начинает сам раздавать каталог медиа по `/media` (статика, только чтение, приватный каталог верификации не затрагивается).
- Разрешить абсолютный базовый адрес медиа для конфигураций, где домен API отличается от домена сайта.
- Проверить сквозной путь: загрузка → главное фото → аватар в шапке и в подборках; при ошибке загрузки показывать причину (тип файла, размер, лимит запросов).

## 5. Сквозная проверка

- Прогнать на реальной БД: регистрация → загрузка фото → назначение главного → создание пространства с загруженной обложкой → открытие карточки пространства.
- Проверить браузером страницы `/profile/me`, `/spaces`, `/spaces/new` на ошибки в консоли и корректные картинки.
- Обновить `API.md` и `SERVER-SETUP.md`: раздача `/media`, загрузка обложки, требования Nginx.

## Технические детали

- `src/routes/__root.tsx` — `links`: `{ rel: "icon", type: "image/png", href: "/favicon.png" }`, удалить `favicon.ico`.
- `src/features/spaces/components/CreateSpaceForm.tsx` — подсказки/ошибки полей, инпут файла обложки.
- `server/src/routes/spaces.ts` — схема `coverUrl`: `url()` → проверка «медиа-путь или https URL»; новый `POST /api/spaces/cover` (или расширение `/api/media` параметром назначения) через `saveProfileFile` без записи в `profile_media`.
- `server/src/index.ts` — `@fastify/static` на `env.MEDIA_DIR` с префиксом из `MEDIA_BASE_URL` (только когда он относительный).
- `server/src/env.ts` / `.env.example` — комментарий про абсолютный `MEDIA_BASE_URL`.
