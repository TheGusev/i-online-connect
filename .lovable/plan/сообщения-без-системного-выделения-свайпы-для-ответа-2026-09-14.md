# Сообщения: без системного выделения + свайпы для ответа

## Результат
Долгое нажатие на сообщение больше не вызывает выделение текста и лупу iOS — открывается только наше меню действий. Свайп по сообщению вправо ставит его в цитату для ответа, свайп влево открывает меню действий. В поле ввода появляется плашка «Ответ на…» с кнопкой отмены, а в истории у ответов видна цитата, по нажатию на которую история прокручивается к исходному сообщению.

## 1. Убрать выделение при нажатии (как уже сделано в голосовых)
- На пузыре сообщения запретить системное выделение и вызов меню iOS: `user-select: none`, `-webkit-user-select: none`, `-webkit-touch-callout: none`, `-webkit-tap-highlight-color: transparent`, `touch-action: pan-y`, `draggable={false}`, `onContextMenu` с отменой стандартного поведения.
- Текст остаётся копируемым через пункт «Скопировать» в нашем меню действий, поэтому потери функции нет.
- Такие же ограничения применить к цитате внутри пузыря и к плашке ответа в поле ввода, чтобы свайп не превращался в выделение.

## 2. Свайпы
- Свайп вправо (порог около 60 px, только при горизонтальном движении, вертикальная прокрутка не перехватывается) — выбрать сообщение для ответа; при достижении порога короткая тактильная отдача, если устройство её поддерживает.
- Свайп влево — открыть то же меню действий, что и по долгому нажатию.
- Во время жеста пузырь плавно сдвигается вслед за пальцем и показывает иконку ответа; после отпускания возвращается на место.
- Удалённые сообщения и сообщения в состоянии отправки/ошибки не отвечаются и не сдвигаются.
- Доступная альтернатива без жеста: пункт «Ответить» в меню действий и обработка клавиатуры.

## 3. Ответ на сообщение
- Над полем ввода — компактная плашка: автор, короткий фрагмент текста (для голосового «Голосовое сообщение», для встречи «Приглашение на встречу») и крестик отмены. Плашка сбрасывается после отправки.
- В истории у сообщения-ответа сверху пузыря выводится цитата; нажатие прокручивает к исходному сообщению с короткой подсветкой. Если исходное удалено — «Сообщение удалено».
- Ответ работает и для текста, и для голосовых, и для приглашений на встречу.

## Технические изменения
- **База:** новая миграция `018_message_replies.sql` — `messages.reply_to_id uuid REFERENCES messages(id) ON DELETE SET NULL` + индекс; существующие строки не меняются.
- **Backend:** `server/src/routes/chat.ts` — приём `replyToId` при отправке текста и голосового с проверкой, что исходное сообщение принадлежит тому же диалогу; выдача цитаты (id, автор, тип, короткий текст, признак удаления) в истории и в WebSocket-событии; `server/src/ws/chat.ts` — та же полезная нагрузка.
- **Фронтенд:** тип `Message` получает `replyTo`; `src/api/endpoints/chat.ts` передаёт `replyToId`; `src/features/chat/hooks.ts` — оптимистичная отправка с цитатой; новый хук жестов `src/features/chat/useSwipeAction.ts`; `MessageBubble.tsx` — блокировки выделения, сдвиг при свайпе, цитата, подсветка при переходе; `MessageActions.tsx` — пункт «Ответить»; `ChatComposer.tsx` — плашка ответа; `src/routes/chat.$id.tsx` — состояние выбранного для ответа сообщения и прокрутка к исходному. Общий чат пространства без изменений.
- Новых пакетов и переменных окружения не требуется. Миграцию нужно применить на сервере (`npm run build`, `npm run migrate`, `pm2 reload ya-online-api`).

## Проверка
- Долгое нажатие на своё и чужое сообщение, на голосовое, на удалённое: выделение и лупа не появляются, меню открывается.
- Свайп вправо и влево, отмена жеста, вертикальная прокрутка истории не ломается.
- Отправка ответа на текст, голосовое и встречу; получение ответа вторым пользователем; цитата после перезагрузки истории.
- Прогон типов и статической сборки, браузерный сценарий на 393×626. Живая проверка на iPhone — за вами.
