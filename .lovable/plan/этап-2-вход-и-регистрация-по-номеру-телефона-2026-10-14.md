# Этап 2: вход и регистрация по номеру телефона

Новый вход по SMS-коду, как в мессенджере. Вход по почте остаётся по ссылке «Войти по почте». Чаты, объявления, сообщества, эфир, голосовые и механизм обновления входа не меняются, а переиспользуются. Telegram и Apple не делаем.

## Что увидит пользователь
1. **Приветствие** (/auth): логотип, «Я онлайн», «Срочные дела — в одном чате», кнопка «Войти по номеру», ссылка «Войти по почте» (старая форма), внизу «Посмотреть объявления рядом», мелкая строка согласия со ссылками на правила.
2. **«Ваш номер»**: поле +7 с маской, автофокус, вставка в любом формате приводится к виду +7…, кнопка «Получить код».
3. **«Введите код»**: 6 ячеек, автоподстановка кода из SMS на iPhone/Android, отправка после 6-й цифры, «Отправить ещё раз через 0:42», «Изменить номер», понятные ошибки (неверный, истёк, слишком много попыток, подождите N секунд).
4. **«Как вас зовут?»** только для нового: имя (обязательно), фото по желанию, затем сразу «Чаты». Длинный онбординг новым не показывается (анкета доступна из профиля).
5. **Гость**: «Рядом» и карточка объявления открываются без входа. «Написать», «Разместить», «Откликнуться», «Вступить» открывают нижнее окно с теми же шагами входа; после входа пользователь возвращается на то же место.
6. Кнопки на всю ширину, зона нажатия от 44px, анимации отключаются при «уменьшении движения».

## Сервер
- **Миграция 026_phone_auth.sql** (только добавления):
  - users: новый `phone` (уникальный), почта и пароль становятся необязательными; проверка «есть почта или телефон».
  - Новая таблица кодов `auth_otps` (хранится только хеш кода, срок 5 мин, счётчик попыток, IP).
  - Новая таблица `user_identities` (провайдер phone/telegram/apple), заполняется для телефона.
  - В профиле `name` уже обязателен, остальные поля (возраст, город, о себе) уже необязательны — менять не нужно.
- **POST /api/auth/phone/request**: номер к виду +7…, разрешённые префиксы из настройки; всегда одинаковый ответ; код из 6 цифр, новый код отменяет прежний, счётчик ошибок не сбрасывается.
- **Лимиты**: пауза 60 → 120 → 300 с на номер, до 5 в час на номер, до 20 в час на IP, суточный лимит SMS. Считаются по таблице кодов в базе — работают и без Redis и не сбрасываются при перезапуске. Превышение: 429 с текстом и временем ожидания.
- **Отправка SMS** через общий интерфейс: «log» (разработка, маскированный номер) и заготовка «http» для будущего провайдера.
- **Текст SMS** — короткий латинский, один сегмент, последняя строка `@домен #123456`. Домен задаётся настройкой: автоподстановка на iPhone работает, только если он совпадает с адресом сайта.
- **Тестовые номера** с фиксированным кодом: выключены по умолчанию, в production только при явном включении.
- **POST /api/auth/phone/verify**: сравнение без утечки по времени, 5 ошибок — код сгорает; новый пользователь создаётся с минимальным профилем; токены выдаются существующими функциями. Ответ `{ token, user, isNew }`. Просроченные коды чистятся при запросах.
- **Гостевой просмотр**: список и карточка объявления без входа, с лимитом запросов, без контактов; автор — имя и значок «Подтверждён». Все действия по-прежнему только после входа.
- **Наблюдение**: счётчики «запрошено / подтверждено» в логе, без кодов и полных номеров.

## Места, которые предполагают почту/возраст/город
Перед правкой проверю и подстрахую: показ возраста в профиле и карточках, настройки аккаунта (смена почты/пароля, удаление с подтверждением по почте), восстановление пароля, письма-уведомления, «Рядом» (город по умолчанию из профиля). Найденное перечислю в отчёте.

## Новые настройки сервера (имена)
`ALLOWED_PHONE_PREFIXES`, `OTP_SECRET`, `SMS_DAILY_LIMIT`, `SMS_PROVIDER`, `SMS_API_URL`, `SMS_API_KEY`, `SMS_SENDER`, `SMS_ORIGIN_DOMAIN`, `TEST_PHONES`, `TEST_PHONES_ENABLED`.

## Чего это не даёт сразу
- Реальные SMS не уходят, пока не выбран провайдер; до этого коды видны только в журнале сервера.
- Миграция 026 применяется на вашем сервере вместе с 024 и 025.

## Технические детали
- Сервер: `server/src/auth/phone.ts` (нормализация, хеш HMAC-SHA256, лимиты), `server/src/sms/` (провайдеры), маршруты в `routes/auth.ts`, публичные GET в `routes/listings.ts` (optional auth + rate limit), `env.ts`.
- Тесты в `server/tests/phone-auth.test.mjs` на временной базе: нормализация, одинаковый ответ, пауза и лимиты, 5 ошибок, новый/существующий пользователь, просрочка, гостевой список без контактов.
- Фронтенд: `src/routes/auth.tsx` (шаги), `src/features/auth/phone/*`, общее окно входа `AuthSheet` с возвратом к действию, `api/endpoints/auth.ts`; гость в `nearby.index.tsx` и `ListingSheet`.
