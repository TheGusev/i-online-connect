# Ревизия «Я Онлайн»: исправления + отчёт в PDF

## Что сейчас есть (проверено по коду)

**Фронтенд** — TanStack Start (SSR + сборка статики `build:static`), маршруты: `/` (лендинг), `/auth`, `/onboarding`, `/feed`, `/spaces`, `/chat`, `/profile/me`, `/profile/$id`, `/verification`, `/safety-center`, `/settings`, `/design-system`. Дизайн-система в `src/components/ds`, состояние — zustand (`useSessionStore`, `useOnboardingStore`), данные — React Query через `src/api`.

**Бэкенд** — Fastify + PostgreSQL (`server/`): auth (Argon2id + JWT + refresh в httpOnly-cookie), onboarding, profile, matching, chat (WebSocket), spaces, settings, trust/verification, media. Миграции 001–003.

## Найденные косяки (подтверждены чтением кода)

1. **Фото профиля не сохраняется при регистрации.** В онбординге `MediaStep` кладёт в черновик только *имя файла* (`photoName`), сам файл никуда не уходит. Загрузка `POST /api/media` существует, но онбординг её не вызывает.
2. **Аватар не приходит в сессию.** Запрос профиля в `server/src/routes/auth.ts` (`/login`, `/register`, `/me`) не отдаёт `avatarUrl`, поэтому в шапке и лентах аватар пустой, хотя в других запросах (chat, spaces, matching) он выбирается из `profile_media`.
3. **Нет редактирования фото.** На `/profile/me` медиа только показывается (`MediaCarousel`), добавить/удалить/сделать главным — нельзя.
4. **Подвал ведёт не туда.** «О проекте» — это анкор `#trust` (не страница), «Правила» → `/safety-center`, «Поддержка» → `/settings` (приватный экран).
5. **Гость видит приватную шапку.** `/safety-center` рендерится в `AppShell public`, а `TopBar` всегда показывает колокольчик с жёстко заданными «3 непрочитанными» и аватар со ссылкой на `/profile/me`.
6. **Подтверждения почты и телефона нет.** В БД есть `users.email_verified` / `phone_verified`, в UI — только надпись «Не подтверждён»; кодов, писем и эндпоинтов нет.

## Что сделаю

### 1. Страницы «О проекте», «Правила», «Поддержка»
- Новый публичный маршрут `/about` — что за проект, принципы (верификация, ограниченная подборка, путь к встрече), как работает AI-знакомство, как устроена безопасность, контакты, ссылки на правила/поддержку. Свой `head()` с уникальными title/description/OG.
- Новый публичный маршрут `/support` — FAQ (вход, фото, верификация, жалобы, удаление аккаунта) + форма обращения (тема, email, текст, валидация zod) → `POST /api/support` с записью в новую таблицу `support_requests`.
- «Правила» ведут на существующий центр безопасности `/safety-center`, ссылка в подвале и в шапке лендинга исправляется.
- Все три страницы получают публичную «гостевую» шапку и общий подвал.

### 2. Публичные экраны без признаков сессии
- Гостевой режим шапки: для неавторизованных вместо колокольчика и аватара — кнопки «Войти» и «Начать».
- Счётчик уведомлений перестаёт быть выдуманным: берётся из реальных данных (непрочитанные диалоги), при нуле бейдж не рисуется.

### 3. Фото профиля: регистрация и редактирование
- В онбординге фото и видео-интро держатся как `File` и после регистрации загружаются через `POST /api/media`; превью в сводке показывает реальную картинку.
- В `auth.ts` запрос профиля дополняется `avatarUrl` из главного фото — аватар появляется сразу после регистрации.
- На `/profile/me` — блок «Фото и видео»: загрузка, удаление, «сделать главным» (новый `PATCH /api/media/:id/primary`), сразу видно в шапке.

### 4. Подтверждение email и телефона
- Миграция `004`: таблица кодов подтверждения (канал, назначение, хэш кода, срок, попытки) + индексы.
- Эндпоинты: запрос кода и подтверждение для email и телефона, лимиты частоты, срок жизни кода 15 минут, максимум 5 попыток.
- Email-письма — через SMTP вашего сервера (nodemailer, `SMTP_*` в `server/.env`); код телефона пока пишется в лог сервера — интерфейс готов, SMS-провайдер подключается позже одной функцией.
- В `/settings` → Аккаунт: кнопка «Подтвердить», ввод кода, повторная отправка с таймером, статус обновляется без перезагрузки. Подтверждённый email повышает уровень доверия (уже учитывается в `/trust`).

### 5. Проверка работоспособности
Сборка и типы, прогон бэкенда с миграциями, сквозной прогон в браузере: лендинг → онбординг с фото → регистрация → лента → профиль (замена фото) → настройки (подтверждение почты) → публичные страницы в режиме гостя. Отдельно смотрю консоль и сетевые запросы на ошибки и лишние повторные запросы.

### 6. Отчёт в PDF
Документ на русском: архитектура (фронтенд/бэкенд/БД со схемой таблиц), карта маршрутов и API, найденные дефекты и что исправлено, результаты проверки, что осталось на будущее (SMS-провайдер, модерация). Готовый файл приложу в чат.
