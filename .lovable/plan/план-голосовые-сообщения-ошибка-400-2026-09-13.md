# План: голосовые сообщения — ошибка 400

## Анализ (шаг 1 из ТЗ — уже выполнен)

Проверил клиентскую отправку (`src/api/endpoints/chat.ts` → `sendVoiceMessage`, `src/features/chat/useVoiceRecorder.ts`, места вызова в `chat.$id.tsx`) против контракта сервера (`server/src/routes/chat.ts`, `POST /conversations/:id/voice`):

1. Поле с tempId называется ровно `clientTempId` — совпадает.
2. Значение — настоящий UUID (`crypto.randomUUID()`), не timestamp.
3. Поле длительности — ровно `durationMs` — совпадает.
4. Длительность в миллисекундах (разница `Date.now()`), не секунды.
5. MediaRecorder выбирает WebM/Opus → WebM → MP4; сервер определяет тип по магическим байтам, оба формата принимает.
6. Один FormData (файл + 2 текстовых поля), отправка через XHR без ручного Content-Type — boundary не теряется.

Вывод: в текущем коде проекта фронт и backend совпадают дословно. Стабильный 400 за 10–22 мс означает либо расхождение с тем, что реально развёрнуто на сервере, либо отказ на ранней валидации, который нужно воспроизвести тестом, а не угадывать.

## Что делаю

### 1. Воспроизведение 400 автотестом
- Новый `server/tests/voice.test.mjs`: реальный multipart-POST (поля `clientTempId`, `durationMs`, файл WebM/MP4 по образцу браузера) через `app.inject` к настоящему обработчику.
- Прогоняю сценарии: валидный WebM, валидный MP4, короткий файл, битый clientTempId, секунды вместо миллисекунд — фиксирую, какой именно отвечает 400, и устраняю причину.

### 2. Понятная причина ошибки в интерфейсе
- Проверяю, что текст ошибки из ответа сервера («Поддерживаются голосовые WebM/Opus и MP4/AAC», «Запись пустая…») доезжает до плашки «Не отправлено» рядом с сообщением; если показывается только общий текст — прокидываю `error.message` в `MessageBubble`.
- Логирую `mediaRecorder.mimeType` в консоль при старте записи (нужно для диагностики на реальных устройствах).

### 3. Диагностика «развёрнуто не то»
- В ответ сервера при 400 на валидации уже входят явные сообщения — оставляю как есть.
- В `SERVER-SETUP.md` добавляю явный чек-лист после обновления: `npm run migrate` (миграции 015–017) и перезапуск PM2 — без этого старая сборка сервера отвечает 400/404 на голосовые.

### 4. Проверки
- `npm run typecheck` (server), `bunx tsgo --noEmit`, `bun run build:static`.
- `bunx vitest run server/tests --passWithNoTests` с тестовой БД — включая новый voice-тест.
- Ручной сценарий retry: отправка без сети → ошибка → «повторить» с тем же `clientTempId` → ровно одно сообщение (дедупликация уже есть на сервере, подтверждаю тестом).

## Ограничение
Тест на реальном iPhone Safari выполнить не могу — после исправления отмечу в отчёте, что его нужно прогнать вручную; код обрабатывает MP4/AAC отдельно.
