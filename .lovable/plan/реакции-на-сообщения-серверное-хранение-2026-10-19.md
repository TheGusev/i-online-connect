# Реакции на сообщения: серверное хранение

Сейчас реакции хранятся только на устройстве (localStorage `chat-reactions`), собеседник их не видит. Переносим на сервер для личных чатов и сообществ. `match_reactions` не трогаем.

## База — миграция `028_message_reactions.sql`
Две таблицы, по одной на каждую существующую таблицу сообщений (так работает настоящий внешний ключ с каскадным удалением):
- `message_reactions` — `message_id → messages(id) ON DELETE CASCADE`, `user_id → profiles`, `emoji text`, `created_at`.
- `space_message_reactions` — то же, ссылка на `space_messages(id)`.
- В обеих: `UNIQUE (message_id, user_id, emoji)`, индекс по `message_id`. Всё через `IF NOT EXISTS` — повторный запуск безопасен.

## Сервер
- Новый модуль `server/src/chat/reactions.ts`: список разрешённых эмодзи, `REACTIONS_PER_USER = 1`, общая логика «поставить / снять / собрать сводку `[{emoji, count, mine}]`». Лимит в одном месте: при 1 новая реакция заменяет прежнюю; при лимите >1 превышение даёт 400 `REACTION_LIMIT`.
- Маршруты:
  - `PUT/DELETE /api/chat/conversations/:id/messages/:messageId/reactions`, тело `{emoji}`.
  - `PUT/DELETE /api/spaces/:id/messages/:messageId/reactions`, тело `{emoji}`.
  - Не участник диалога / не член сообщества — 403; эмодзи не из списка — 400; сообщение не из этого чата — 404.
- Списки сообщений (обе ленты) и ответ маршрутов возвращают `reactions: [{emoji, count, mine}]`, `mine` — для запрашивающего.
- Обновление у собеседника:
  - Личный чат: новое WebSocket-событие `reaction` с `messageId` и счётчиками (без `mine`), клиент пересчитывает `mine` сам по своей реакции — через тот же канал, что и новые сообщения.
  - Сообщества: реакции приходят вместе с уже существующим периодическим опросом списка сообщений.

## Клиент
- `src/api`: типы `MessageReaction`, поле `reactions` у сообщений, функции поставить/снять для обоих видов чатов.
- Хуки `useToggleReaction` (личный и сообщество): оптимистично меняют кеш сообщения, при ошибке откатывают.
- `MessageBubble`, `MediaAlbum`, `MessageActions` читают реакции из сообщения вместо localStorage; старые локальные реакции игнорируются (хранилище больше не читается).
- `ReactionChip`: эмодзи + число (если >1), мои подсвечены розовым. Нижняя строка (реакции слева, время справа) без изменений.
- Обработчик WebSocket в `chat.$id.tsx` применяет событие `reaction` к кешу.

## Тесты
`server/tests/message-reactions.test.mjs` (по шаблону `space-messages.test.mjs`): поставить, заменить, снять, чужая реакция сохраняется и учитывается в count, посторонний получает 403, неизвестный эмодзи — 400. Плюс клиентский тест на оптимистичное обновление/откат сводки.
