# Полноценные чаты между реальными пользователями

## Что не так сейчас (проверено по коду)

- **Входящие сообщения не появляются без перезагрузки.** Экран диалога открывает WebSocket, но не обрабатывает события `message`/`read` — обновляется только «печатает…», причём индикатор, включившись, никогда не гаснет.
- **Нет уведомлений о новых сообщениях.** Сервер при отправке сообщения не создаёт запись в уведомлениях и не пушит получателю; в колокольчике есть только события «Рядом». На вкладке «Чат» в меню нет счётчика непрочитанных.
- **История без подгрузки.** Сервер отдаёт максимум 500 сообщений одним запросом, старые сообщения недоступны; нет статуса «прочитано».
- **В чат нельзя попасть с профиля.** Кнопка «Написать» в профиле и кнопка «Отправить» в окне первого сообщения ведут просто на список диалогов; текст первого сообщения не отправляется. Нет способа создать диалог с человеком напрямую.
- **Дубли диалогов при взаимном лайке.** Повторный лайк после совпадения создаёт ещё один пустой диалог с тем же человеком.
- **Если адрес WebSocket не задан**, работает старая «имитация» с фальшивым «печатает…».

## Что сделаем

### 1. Сообщения в реальном времени
- Экран диалога подписывается на события сокета: новое сообщение сразу добавляется в переписку (без дублей с собственными сообщениями), событие `read` переводит свои сообщения в статус «прочитано».
- «Печатает…» гаснет через ~3 секунды; при наборе текста отправляем событие `typing` собеседнику (не чаще раза в 2 секунды).
- Автопереподключение сокета при обрыве (с задержкой) и обновление списка при возврате на вкладку.
- Убираем имитацию: если адрес сокета не задан, используем адрес текущего сайта (`wss://<домен>/ws`).
- Список диалогов и счётчики обновляются при получении любого события чата.

### 2. Уведомления
- При отправке сообщения сервер создаёт уведомление `new_message` получателю (с именем отправителя, кратким текстом и ссылкой на диалог) и пушит его через канал уведомлений. Если получатель прямо сейчас открыт в этом диалоге — уведомление не создаём, только доставляем сообщение.
- Колокольчик показывает «Новое сообщение от …» и ведёт в диалог; при открытии диалога такие уведомления помечаются прочитанными.
- Вкладка «Чат» в нижнем и боковом меню получает розовый бейдж с числом непрочитанных диалогов.
- Всплывающий toast «Новое сообщение от …» при получении, если пользователь не в этом диалоге.
- Уведомления не создаются для заблокировавших друг друга пользователей и не отправляются демо-профилям (`is_seed`).

### 3. История
- Постраничная загрузка: сервер отдаёт последние 50 сообщений и умеет отдавать более старые по курсору; на экране появляется кнопка/автоподгрузка «Показать более ранние» при прокрутке вверх с сохранением позиции.
- Разделители по дням («Сегодня», «Вчера», дата).
- Статусы своих сообщений: «отправляется» (оптимистично добавляем сразу), «отправлено», «прочитано»; при ошибке — пометка и повтор отправки.
- Список диалогов: непрочитанные выделяются, показывается «Вы:» перед своим последним сообщением.

### 4. Начало диалога
- Новый запрос на сервере: «открыть диалог с пользователем» — возвращает существующий диалог или создаёт новый с учётом настройки приватности собеседника («все / только проверенные / только совпадения»), блокировок и запрета для демо-профилей (вернёт понятное сообщение «Это демо-профиль для примера»).
- Кнопка «Написать» в профиле открывает конкретный диалог.
- Окно первого сообщения после совпадения реально отправляет набранный текст и переводит в диалог.
- Исправляем дубли: при взаимном лайке сервер переиспользует диалог по `match_id`.

### 5. Проверка
- Локальная БД + два реальных аккаунта: переписка в двух окнах одновременно, уведомление и бейдж у второго пользователя, подгрузка истории, статус «прочитано», старт диалога с профиля.
- Обновить `API.md` (новые запросы) и заметку в `SERVER-SETUP.md` про `VITE_WS_URL`.

## Технические детали

**Backend (`server/`)**
- `routes/chat.ts`: `GET /conversations/:id/messages?before=<iso>&limit=50` (обратный курсор), `POST /conversations` `{ participantId }` с проверкой `privacy.who_can_message`, `blocks`, `profiles.is_seed`; в `POST …/messages` и `…/meetings` — вставка в `notifications` (`kind='new_message'`, payload `{ conversationId, fromName, preview }`) и `publishUserEvent`, пропуск если получатель есть в комнате диалога (`isInRoom` в `ws/chat.ts`); ответ включает `readAt`. Добавить `GET /conversations/unread-count`.
- `ws/chat.ts`: экспорт `isInRoom(conversationId, userId)` (хранить userId у сокета), `read` событие уже есть.
- `routes/matching.ts`: перед созданием диалога — `SELECT id FROM conversations WHERE match_id = $1`; вернуть `conversationId` в ответе на лайк.
- Миграция `010_chat_notifications.sql`: индекс `messages (conversation_id, created_at DESC, id)`, уникальный индекс на `conversations(match_id) WHERE match_id IS NOT NULL`, частичный индекс уведомлений по `payload->>'conversationId'`.
- Rate-limit на отправку сообщений через существующий механизм (например 60/мин на пользователя).

**Frontend (`src/`)**
- `features/chat/useChatSocket.ts`: обработка `message`/`read`/`typing` с таймаутом, метод `sendTyping`, реконнект, fallback URL.
- `features/chat/hooks.ts`: `useInfiniteQuery` для сообщений, оптимистичная отправка с `status: "sending" | "sent" | "read" | "failed"`, `useOpenConversation`, `useUnreadChatCount`.
- `routes/chat.$id.tsx`: подписка на события, дневные разделители, подгрузка вверх, повтор неудачных.
- `features/notifications/hooks.ts`: `describeNotification` для `new_message` → ссылка на `/chat/$id`; toast и инвалидация `["chat", …]` при событии.
- `components/layout/BottomNav.tsx`, `SideNav.tsx`: бейдж непрочитанных из `useUnreadChatCount`.
- `ProfileActionBar`, `FirstMessageSheet`: вызов `useOpenConversation` + переход в `/chat/$id`.
- `api/endpoints/chat.ts`, `api/types.ts`: новые методы и поля.
