# Короткий первый вход и подтверждённые способы связи

## Сделано
- Все способы входа используют общий короткий шаг: имя, возраст 18–100, город, необязательное фото, обязательный чекбокс 18+; возраст проверяется и сервером. Пока возраст пустой/0, шаг показывается повторно. После сохранения — `/chat`.
- Полная анкета сохранена и доступна через «Заполнить анкету». Пустой возраст скрыт в карточках; собственные пустые состояния сохранены. Пустое описание чужого профиля — «Профиль не заполнен».
- В своём профиле — закрываемое предложение защитить аккаунт для пользователей без проверенной почты/Яндекс/Telegram; после короткого шага — однократная подсказка видео-проверки. Закрытие запоминается отдельно для каждого пользователя.
- SMS-вход и привязка выключены по умолчанию флагом; код не удалён. Отключённые запросы отвечают 404 без записи OTP и отправки SMS.
- Срочная продажа, ставка и бронь принимают Яндекс/Telegram identity, проверенную почту либо проверенный телефон. Общий helper используется и автоматическими бронями. Новый отказ — CONTACT_NOT_VERIFIED; клиент предлагает подтверждение почты/способы связи.
- Подтверждение почты через существующий SMTP: 6 цифр, HMAC с привязкой к пользователю/адресу, 10 минут, максимум 5 попыток, одноразовое использование, блокировки для параллельных запросов, постоянные лимиты аккаунта/IP. Контакты и коды не журналируются.

## Миграция и окружение
- Новая только `035_email_confirmation_limits.sql`: ADD COLUMN IF NOT EXISTS ip + индекс в существующей contact_confirmations. Нужна для постоянного IP-лимита между процессами и перезапусками. Остальные миграции не изменены.
- Новые `PHONE_LOGIN_ENABLED=false` (сервер), `VITE_PHONE_LOGIN_ENABLED=false` (клиент). SMS включать только согласованным изменением обеих.
- SMTP и HMAC используют существующие переменные; новых библиотек и секретов нет.
- Выкладка: `npm run migrate` из server → обновление/перезапуск API с окружением → `npm run build:static` и замена dist/static → проверка SMTP и настроенных OAuth на рабочем домене. Ранее выданные email-коды нужно запросить заново после перехода на HMAC.

- 123/123 клиентских теста; 6/6 новых API-тестов на изолированной PostgreSQL, включая SMS 404 без изменений таблицы, границы возраста, контакты для ставок, просроченные/неверные/параллельные коды, смену адреса и лимиты.
- 29/29 выбранных серверных регрессий входа, OAuth и срочных мутаций.
- Полный серверный набор: 133 passed, 3 failed из-за отдельных настроек старых тестов: admin не получил DATABASE/JWT, trust требует TRUST_TEST_DATABASE_URL, voice ожидает другой тестовый сокет PostgreSQL. Тесты сохранены; это не проверка рабочей базы.
- Типы сервера проверены tsgo без ошибок; серверный tsc отдельно не запускался. Автоматическая проверка клиента — build OK.
- Lint изменённых клиентских файлов: 0 ошибок; общий lint не чистый (1655 ошибок, преимущественно старое форматирование; чужие файлы массово не переписаны).
- Настоящий изолированный API в браузере: email-регистрация → короткий шаг → отказ для возраста 17 → сохранение 18 → /chat; обе подсказки скрыты после закрытия и перезагрузки; SMTP-письмо доставлено и код подтверждён через интерфейс. В этих действиях не было pageerror; тестовая среда не обслуживала realtime и имела существующее предупреждение гидратации viewport.
- Рабочая БД, рабочая почта, реальные Яндекс/Telegram и физический iPhone/Safari не проверены: доступ/настройки владельца отсутствуют. Изолированный SMTP/API — не подмена production и не основание заявлять, что рабочие провайдеры настроены.
