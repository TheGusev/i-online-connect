# API «Я Онлайн» — каркас backend

Node.js 22 + Fastify + PostgreSQL. Отдельное приложение: свой `package.json`,
своя сборка, свой процесс под PM2. К фронтенд-бандлу отношения не имеет.

## Быстрый старт локально

```bash
cd server
cp .env.example .env        # пропишите DATABASE_URL и секреты JWT
npm install
npm run migrate             # создаст схему в PostgreSQL
npm run dev                 # http://127.0.0.1:4000/api/health
```

Затем во фронтенде: `VITE_API_URL=http://localhost:4000/api`,
`VITE_WS_URL=ws://localhost:4000/ws` — и `npm run dev` в корне проекта.

## Что уже готово

- Регистрация, вход, refresh-токены с ротацией и отзывом, argon2id-хеши.
- Проверка доступа: `requireAuth`, `assertConversationAccess`, `assertSpaceMembership`.
- Профили (свой и чужой), приватность, блокировки.
- Дневная подборка с фиксацией на сутки, реакции, автосоздание пары и диалога.
- Чат (HTTP) + WebSocket-хаб для `message` / `typing` / `read`.
- Сообщества: список, создание, вход/выход, RSVP, групповой чат.
- Онбординг одним объектом, доверие, жалобы, верификация селфи, настройки.

## Правила, которые нельзя нарушать

1. Только параметризованные SQL-запросы (`$1`, `$2`) — никакой склейки строк.
2. Каждый эндпоинт с личными данными закрыт `requireAuth` + проверкой владения.
3. Секреты только в окружении. `.env` не коммитится, права `chmod 600`.
4. Наружу отдаём DTO из `src/types.ts`, а не строки таблиц: иначе утекут
   координаты, e-mail и служебные счётчики.
5. Одинаковый текст ошибки для «нет такого email» и «неверный пароль».

установка сервера — в `../SERVER-SETUP.md`.
