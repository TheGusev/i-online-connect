# Безопасность входа

## Изменения

- Вход по SMS ищет только подтверждённый номер или phone identity. Чужая неподтверждённая заявка очищается, но аккаунт сохраняется. Создание/привязка и изменение идентификатора происходят транзакционно под блокировкой номера.
- PATCH настроек принимает только email, currentPassword и language. Прямой phone отклоняется с 400. Смена email требует текущего пароля, если он задан, и сбрасывает email_verified.
- Привязка номера требует авторизации и SMS-кода, связанного с текущим пользователем и назначением link. Код входа, чужой код и повторное использование не подходят. Подтверждённый чужой номер — 409. При смене номера прежняя phone identity удаляется.
- Старые телефонные подтверждения отключены с 410; код в журнал больше не выдаётся.
- Восстановление доступно только email_verified = true, для активных незаблокированных аккаунтов. Шесть цифр, HMAC-хеш, 15 минут, пять попыток. Новый пароль проверяется правилом регистрации; пароль и отзыв всех refresh-токенов обновляются в одной транзакции.
- Запрос восстановления всегда даёт 204 для корректного email: отсутствующий/неподтверждённый адрес, превышение лимита или отсутствие SMTP не раскрываются. Лимиты записываются для всех адресов: паузы 60/120/300 секунд, пять запросов на адрес в час, двадцать на IP в час, общий суточный лимит SMS_DAILY_LIMIT.
- Без SMTP_HOST конфигурация возвращает passwordResetEnabled: false; ссылка «Забыли пароль?» скрыта. При недоступном чтении конфигурации она также не показывается.
- Клиент: восстановление в существующем экране входа; привязка телефона через окно в аккаунте. Новые библиотеки не добавлены, ранее объявленные зависимости сервера установлены для тестирования.

## Новые маршруты

| Метод | Путь | Доступ / результат |
| --- | --- | --- |
| GET | /api/auth/config | Публично; passwordResetEnabled |
| POST | /api/auth/phone/link/request | Авторизован; { phone }; 204, лимиты 429 |
| POST | /api/auth/phone/link/verify | Авторизован; { phone, code }; verified или 409 |
| POST | /api/auth/password/reset/request | Публично; { email }; 204 |
| POST | /api/auth/password/reset/confirm | Публично; { email, code, newPassword }; 204 или 400 |

POST /api/confirm/phone/request и /verify теперь возвращают 410 после проверки авторизации.

## Миграция и env

Единственная новая миграция: `server/migrations/033_auth_security.sql` — additive: ADD COLUMN IF NOT EXISTS purpose/user_id в auth_otps, CREATE TABLE IF NOT EXISTS auth_email_codes и индексы IF NOT EXISTS. Миграции 001–032 не изменялись.

Новых env нет. Используются существующие:

- Почта: SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, MAIL_FROM.
- SMS: SMS_PROVIDER, SMS_API_URL, SMS_API_KEY, SMS_SENDER, SMS_ORIGIN_DOMAIN, ALLOWED_PHONE_PREFIXES.
- Хеши/лимиты: OTP_SECRET (fallback JWT_REFRESH_SECRET), SMS_DAILY_LIMIT.
- Для тестов: TEST_PHONES_ENABLED и TEST_PHONES; на рабочем сервере тестовые коды следует отключать.

На собственном сервере применить `npm run migrate` из server/ и обновить/перезапустить API перед выкладкой клиента. Включение восстановлений определяется сервером, клиентский VITE-флаг не нужен.

## Проверки

- `node --experimental-strip-types --test server/tests/auth-security.test.mjs server/tests/phone-auth.test.mjs`: 16/16 прошли, включая вход с чужим неподтверждённым номером, код/авторизацию/409 привязки, текущий пароль при смене email, 410 старых маршрутов, одинаковые 204 и лимиты, сроки/попытки, запрет сброса непроверенной почты и отзыв всех refresh.
- `bun test src/features/auth/phone/phone.test.ts src/lib/scroll-lock.test.ts`: 7/7 прошли. Vitest и прямой Node несовместимы с форматом/безрасширительными импортами этих существующих клиентских тестов; повторный запуск Bun успешен.
- Все 33 миграции применены на отдельной PostgreSQL в sandbox. Новая 033 проверена на настоящем SQL-движке; рабочие данные не использовались.
- В браузере пройдено: проверенная тестовая почта → письмо локального SMTP → код и новый пароль → вход новым паролем → настройки → запрос SMS → подтверждение → номер прочитан из настроек. SMS-доставка внешнему провайдеру не проверялась: использован тестовый номер. Запросы auth/settings перенаправлены на изолированный настоящий API; посторонние запросы приложения не участвовали в проверке.
- Автоматическая проверка приложения: build OK; сохранён вид существующего входа.
- **Не проверены:** tsc сервера (не запускался), рабочая БД/миграция на сервере владельца, рабочие SMTP/SMS и доставляемость писем/SMS. Проверка тестовой PostgreSQL не заменяет проверку рабочего сервера.
