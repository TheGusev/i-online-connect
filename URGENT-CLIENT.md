# Клиент срочных сделок

## Результат

- В категории «Срочно» пять типов. Для продажи: рыночная подсказка 75%/55%, старт и приватный минимум, проверка двух фото, сроки с default 6 часов, список ступеней с временем и ценой.
- Для остальных типов поля по заданию. Маршрут/выезд/места и время забора записываются в описание: существующий сервер не принимает отдельных полей. Покупка использует priceMinor как потолок, помощь — как необязательный бюджет.
- Общие цены и действия в карточке, нижнем листе и отдельном объявлении: текущая цена, скидка, следующий шаг, окончание снижения, серверная подсказка, фактическое число наблюдателей. Минимум покупателю не вычисляется.
- Ручная бронь 15/30/60 минут, фиксация цены по ответу сервера, своя/чужая бронь, отмена, моя цена/изменение/отмена, наблюдение. Ошибки переводятся на русский; PHONE_REQUIRED открывает подсказку. Автор получает ставки, минимум, имя/цену/время брони, продано/снять/неявка.
- Опрос только срочных деталей каждые 10 секунд; срочной ленты и UrgentStrip — каждые 15 секунд. Срочный список сортируется по ближайшему окончанию, бронь исключается. Общие BottomSheet используют существующие scroll-lock и motion/reduced-motion классы; новые зависимости не добавлены.
- Три вида уведомлений ведут в объявление или перезапуск. Форма читает прошлый лот, предзаполняет текст и цены, проверяет верхнюю границу старта; фото можно перенести кнопкой с повторной загрузкой (старые файлы нельзя перепривязать). Для final_call, в котором сервер передаёт только listingId, актуальная цена читается через существующий GET лота.

## Проверки и ограничения

- 29 тестов «Рядом» и scroll-lock прошли, включая клиент/сервер на 343 сочетаниях срока/ступеней/времени, две фотографии, границы цены, перезапуск и сортировку.
- Автоматическая сборка/проверка типов приложения: последний журнал `build OK`.
- Браузер: публичный «Рядом» открывается, «Разместить» у гостя открывает существующий телефонный вход без перехода с экрана.
- Полный путь создания/загрузки/брони/ставки/продажи **не проверен с настоящим аккаунтом и API**: доступной авторизованной сессии своего сервера нет. Моки и обход входа не использовались.
- **На телефоне не проверены** раскладка пяти плиток/графика, клавиатура 16px, вложенные окна, свайп закрытия, таймеры и reduced-motion. Проверка гостевого экрана в desktop-браузере не заменяет эти проверки.
- Существующий API удаляет owner activeReservation из DTO сразу при истечении. Пока лист открыт, клиент сохраняет последнюю виденную бронь и разрешает «Не пришёл» по её сроку; **после открытия уже истёкшей брони с нуля данных о покупателе нет**. Сервер не менялся, поэтому этот случай нельзя надёжно восстановить клиентом.
- 031 по-прежнему нужно применить и обновить собственный сервер для реальной работы новых действий.
